## Purpose/Why:
---

Value categories are fundamental to understanding how C++ handles expressions and enables crucial features like move semantics, perfect forwarding, and function overloading resolution. They determine whether an expression can be moved from, assigned to, or how it binds to references. This classification system became essential with C++11's introduction of rvalue references and move semantics, allowing the compiler to optimize resource management and enable zero-cost abstractions.

## Core Explanation:
---

C++ classifies every expression into one of five value categories that form a taxonomy:

**Primary Categories (C++11):**
- **lvalue**: Has identity and cannot be moved from. Can take its address with `&`.
- **xvalue** (expiring value): Has identity and can be moved from. Result of operations that produce rvalue references.
- **prvalue** (pure rvalue): Does not have identity but can be moved from. Temporary objects and literals.

**Composite Categories:**
- **glvalue** (generalized lvalue): lvalue + xvalue (expressions with identity)
- **rvalue**: xvalue + prvalue (expressions that can be moved from)

The key properties:
- **Identity**: Can you take the address of the expression?
- **Movability**: Can resources be "stolen" from this expression?

## Related Concepts:
---

- **Move Semantics**: Value categories determine when move constructors/assignment operators are called
- **Perfect Forwarding**: Uses universal references and value category preservation
- **Reference Binding**: Different reference types bind to different value categories
- **Function Overloading**: Overload resolution considers value categories
- **Template Argument Deduction**: Auto and template deduction rules depend on value categories

## Examples:

```cpp
#include <iostream>
#include <string>

class MyClass {
public:
    std::string data;
    MyClass(const std::string& s) : data(s) {}
};

MyClass createObject() {
    return MyClass("temporary");  // Returns prvalue
}

int main() {
    // === LVALUES ===
    int x = 42;           // x is lvalue - has identity, can't be moved from
    int& ref = x;         // ref is lvalue - references are always lvalues
    int* ptr = &x;        // Can take address - confirms it's lvalue
    
    MyClass obj("hello"); // obj is lvalue
    obj.data = "world";   // Can assign to lvalue
    
    // === PRVALUES ===
    int a = 5 + 3;        // 5 + 3 is prvalue - no identity, can be moved from
    MyClass temp = createObject(); // createObject() returns prvalue
    
    // === XVALUES ===
    MyClass&& rref = std::move(obj); // std::move(obj) is xvalue
    // obj still exists but is in "moved-from" state
    
    // === GLVALUES (lvalue + xvalue) ===
    // Both obj (lvalue) and std::move(obj) (xvalue) have identity
    
    // === RVALUES (xvalue + prvalue) ===
    // Both std::move(obj) and createObject() can be moved from
    
    // === REFERENCE BINDING EXAMPLES ===
    int& lref1 = x;                    // lvalue binds to lvalue reference
    // int& lref2 = 42;                // ERROR: prvalue can't bind to lvalue reference
    
    int&& rref1 = 42;                  // prvalue binds to rvalue reference
    int&& rref2 = std::move(x);        // xvalue binds to rvalue reference
    // int&& rref3 = x;                // ERROR: lvalue can't bind to rvalue reference
    
    const int& cref1 = x;              // lvalue binds to const lvalue reference
    const int& cref2 = 42;             // prvalue binds to const lvalue reference
    const int& cref3 = std::move(x);   // xvalue binds to const lvalue reference
    
    // === FUNCTION OVERLOADING ===
    auto process = [](const std::string& s) { 
        std::cout << "lvalue version: " << s << std::endl; 
    };
    auto processRvalue = [](std::string&& s) { 
        std::cout << "rvalue version: " << s << std::endl; 
    };
    
    std::string str = "test";
    // process(str);              // Would call lvalue version
    // processRvalue(std::move(str)); // Would call rvalue version
    
    return 0;
}
```

**Q: What's the difference between glvalue and rvalue composite categories?**
A: glvalue = lvalue + xvalue (expressions with identity), rvalue = xvalue + prvalue (expressions that can be moved from)

**Q: Can you bind an rvalue reference to an lvalue directly?**
A: No, you need std::move() to cast the lvalue to an xvalue, which can bind to rvalue references

**Q: What value category is the result of std::move()?**
A: xvalue - it has identity but can be moved from
