# **Core Explanation:**

In C++ [[C++ - Exception Handling]], the `throw` keyword is used to **signal** that an exceptional condition or error has occurred. It explicitly raises an exception, interrupting the normal flow of program execution.

## Purpose

The primary purpose of `throw` is to indicate that something unexpected or erroneous has happened that prevents the current block of code from continuing normally. When a `throw` statement is executed, the program searches for an appropriate exception handler ([[catch]] block) to transfer control to. This allows for centralized error handling rather than dealing with error codes at every step.

## Syntax

There are two primary forms of the `throw` statement:

1.  **Throwing an expression:**
    ```cpp
    throw expression;
    ```
    >  The `expression` determines the **type** and **value** of the exception being thrown. This can be a literal value, a variable, or an object. The type of the `expression` is crucial, as it determines which `catch` block (if any) will handle the exception.

2.  **Re-throwing the current exception:**
    ```cpp
    throw;
    ```
    *   ==This form, with no operand, is **only valid inside a `catch` block** (or a function called directly from a `catch` block).==
    *   It re-throws the *exception object that is currently being handled* by the `catch` block. This is useful if a handler can only partially handle an exception and needs to pass it on to another handler further up the call stack.

## How it Works

1.  **Signal Exception:** When `throw expression;` is executed, an exception object is created from the `expression` (often involving a copy, though optimization can occur).
2.  **Stop Execution:** The normal execution flow within the current block immediately stops. No further statements in the current block after the `throw` are executed.
3.  **Stack Unwinding:** The program begins *unwinding the stack*. This means it exits the current block, destructing any local objects created within that block (this is key to RAII - Resource Acquisition Is Initialization). It continues exiting blocks and destructing local objects as it moves up the [[Call Stack]].
4.  **Handler Search:** During stack unwinding, the runtime system looks for an enclosing `try` block followed by a `catch` handler that matches the type of the thrown exception. The search proceeds up the call stack from the point of the `throw`.
5.  **Control Transfer:** If a matching `catch` block is found, the stack unwinding stops, and control is transferred to that `catch` block. The thrown object/value is passed to the `catch` parameter.
6.  **Unhandled Exception:** If the stack is unwound all the way to the `main` function (or the start of a thread) without finding a matching handler, the program typically calls `std::terminate()`, which usually aborts the program.

## What Can Be Thrown?

You can `throw` almost any type of value or object in C++:

*   **Primitive Types:** `int`, `double`, `bool`, `const char*`, etc. (As shown in the initial example with `throw (age);`).
*   ==**Class Objects:** This is the **preferred method**.==
    *   **Standard Library Exceptions:** Objects of classes derived from std::exception (like `std::runtime_error`, `std::logic_error`, `std::out_of_range`, etc., defined in `</stdexcept>` or `</exception>`). These provide a standard way to report errors and typically include a `.what()` method describing the error.
    *   ==**Custom Exception Classes:**== You can define your own classes (often inheriting from `std::exception`) to represent specific error conditions in your application.
*   **Pointers:** While possible, throwing raw pointers is generally discouraged compared to throwing objects or well-defined primitive types.

>**Best Practice:** Throw objects (by value), preferably of types derived from `std::exception`, and [[catch]] them by `const` reference (`const ExceptionType&`).

## Relationship with `try` and `catch`

*   `throw` is the mechanism used to **initiate** the exception handling process.
*   It is typically used *inside* a `try` block (or a function called from within a `try` block) where errors might be detected.
*   The exception signaled by `throw` is intended to be caught and handled by a corresponding `catch` block associated with an enclosing `try` statement. Without a `try`/`catch` structure somewhere up the call stack, a `throw` will lead to program termination.

# **Examples:**

## Example Context Revisited

```cpp
try {
    int age = 15;
    if (age >= 18) {
        cout << "Access granted - you are old enough.";
    } else {
        // Problem detected: age is too low.
        // Signal this exceptional condition using throw.
        throw (age); // Execution stops here, an int exception (value 15) is raised.
                     // Stack unwinding begins, searching for a catch handler.
    }
    // This line is skipped if the throw occurs.
    cout << "Exiting try block normally." << endl;
}
catch (int myNum) { // This handler matches the thrown int exception.
    cout << "Access denied - You must be at least 18 years old.\n";
    cout << "Age is: " << myNum; // myNum receives the value 15.
}
```

In this example, the throw (age); statement is the core action that triggers the exception handling mechanism when the if condition (age < 18) is true. It passes the value of age as the exception data.
