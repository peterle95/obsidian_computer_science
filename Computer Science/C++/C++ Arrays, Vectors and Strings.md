const currentPage = dv.current();

// Split content into lines
const lines = content.split('\n');
let flashcardLines = [];
let inCodeBlock = false;

// Collect all potential flashcard lines - simplified approach
for (let i = 0; i < lines.length; i++) {
    const line = lines[i];
    
    // Track code blocks
    if (line.trim().startsWith('```')) {
        inCodeBlock = !inCodeBlock;
        continue;
    }
    
    // Skip everything inside code blocks
    if (inCodeBlock) continue;
    
    // Check if line contains flashcard separator
    if (line.includes(';;')) {
        flashcardLines.push(line);
    }
}

const filteredLines = flashcardLines.filter(line => {
    // Only filter out lines that are clearly part of the JavaScript code
    // Be more specific with patterns to avoid false positives
    return !(
        line.trim().startsWith('const ') ||
        line.trim().startsWith('let ') ||
        line.trim().startsWith('function ') ||
        line.trim().startsWith('return ') ||
        line.trim().startsWith('if (') ||
        line.trim().startsWith('for (') ||
        line.trim().startsWith('while (') ||
        line.includes('dataviewjs') ||
        line.includes('content.split') ||
        line.includes('flashcardLines') ||
        line.includes('this.container') ||
        line.includes('addEventListener') ||
        line.includes('console.log') ||

    );
});

const flashcards = [];

# **Core Explanation:**

## Arrays

Arrays are fundamental data structures in C++ that store collections of elements in contiguous memory locations.

### Basic Characteristics
- Collection of same-type elements
- Stored in contiguous memory (no gaps)
- Zero-based indexing
- Fixed size at compile time

### Array Declaration Contexts
```cpp
// Global variable (avoid when possible)
int globalArr[5];

// Local variable
void func() {
    int localArr[5];
}

// Function argument (decays to pointer)
void processArray(int arr[], int size);

// Class member
class MyClass {
    int memberArr[5];
};
```
### Multidimensional Arrays
C++ supports multidimensional arrays as arrays of arrays:

```cpp
// 2D array (3 rows, 4 columns)
int matrix[3][4];

// Accessing elements
matrix[1][2] = 42;
```

## Limitations of Arrays

### 1. Size Constraints
- Size must be known at compile time
- Cannot be resized dynamically
- Size must be a constant expression

### 2. Safety Issues
- No built-in bounds checking
- Possible buffer overflows
- No size information stored with array

### 3. Usage Restrictions
- Cannot be copied with assignment operator
- Decay to pointers when passed to functions
- No built-in operations (like finding size)

## C-Style Strings
C-style strings are character arrays terminated by a null character (`\0`).

```cpp
char str[] = "Hello"; // Compiler adds \0 automatically
char str2[6] = {'H', 'e', 'l', 'l', 'o', '\0'};
```

### Limitations
- Fixed size
- No bounds checking
- Manual memory management
- Error-prone string operations

## Modern Alternatives

### std::vector
`std::vector` provides a more robust alternative to raw arrays:

```cpp
#include <vector>

std::vector<int> vec = {1, 2, 3, 4, 5};
vec.push_back(6);  // Dynamic resizing
int size = vec.size();  // Built-in size tracking
```

#### Advantages over Arrays
- ==Dynamic size==
- Automatic memory management
- Bounds checking (with `at()` method)
- Rich set of member functions
- Copy and assignment support

### std::string
`std::string` offers a safer and more convenient alternative to C-style strings:

```cpp
#include <string>

std::string str = "Hello";
str += " World";  // Easy concatenation
int length = str.length();  // Built-in length
```

#### Key Features
- Dynamic sizing
- Safe memory management
- Rich set of string operations
- Support for various character types
- Standard library integration

## Best Practices

1. Prefer `std::vector` over raw arrays
2. Use `std::string` instead of C-style strings
3. Use `array` for fixed-size arrays when needed
4. Always validate array indices
5. Consider string_view for string references
## Common Pitfalls to Avoid
1. Buffer overflows
2. Off-by-one errors
3. Forgetting null termination in C-strings
4. Incorrect array size calculations
5. Memory leaks with dynamic arrays
