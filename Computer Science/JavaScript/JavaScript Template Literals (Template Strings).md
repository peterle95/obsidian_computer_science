## Purpose/Why
---

Template literals solve the problem of ==writing and composing strings that include dynamic values==, multi-line text, and simple templating without concatenation or escape-heavy syntax. They ==improve readability and reduce errors when building strings in JavaScript==, which is essential for constructing UI, generating HTML, logging, and creating readable programmatic text. In computer science terms, they simplify string interpolation and support clearer source code for data representation and program output.

## Core Explanation
---

Template literals are string <mark style="background: #ADCCFFA6;">literals enclosed by backticks (`) instead of single or double quotes</mark>. They provide:

- Interpolation: embed expressions using `${expression}` which are evaluated and converted to strings.
- Multi-line strings: preserve newlines and spacing as written without `\n`.
- Tagged templates: functions that process a template literal's parts (strings and values) for custom formatting, localization, or sanitization. Key characteristics:
- Expression interpolation supports any valid JavaScript expression.
- Template literal values are coerced to strings using standard conversion.
- Tagged templates receive an array of literal segments and the expression values, allowing advanced processing (e.g., escaping or localization). How it works:
- At runtime, the template literal is parsed into literal segments and expression values. For a simple `${...}`, the expression is evaluated and replaced with its string result. For tagged templates, the tag function is called with the segments and values and returns the final string (or any other value).

## Related Concepts
---

- String concatenation: using `+` to join strings — more verbose and error-prone for complex constructions.
- String methods: `.replace()`, `.slice()` etc. — used for manipulating strings after creation.
- Template engines (e.g., Mustache, Handlebars): full templating solutions for complex templating needs (loops, conditionals) — template literals are lightweight and inline.
- Localization/i18n: tagged templates are often used to integrate localization logic.
- Escaping and sanitization: tagged templates can implement safe HTML escaping to prevent XSS.

Examples
---
```javascript
// Example 1: Basic interpolation and multi-line
const name = "Ava";
const items = 3;

// Using a template literal for readable interpolation and multi-line output
const message = `Hello ${name},
You have ${items} new notifications.
Regards,
Team`;
// message will be:
// "Hello Ava,
// You have 3 new notifications.
// Regards,
// Team"

// Example 2: Expression interpolation (any valid JS expression)
const a = 5, b = 7;
console.log(`Sum of ${a} and ${b} is ${a + b}.`); // "Sum of 5 and 7 is 12."

// Example 3: Tagged template for simple HTML escaping (prevent XSS)
function escapeHTML(strings, ...values) {
  // strings: array of literal parts
  // values: evaluated expressions
  const escape = s => String(s)
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#39;");
  // Recombine literal parts and escaped values
  return strings.reduce((result, str, i) => result + str + (i < values.length ? escape(values[i]) : ""), "");
}

const userInput = "<script>alert('x')</script>";
const safe = escapeHTML`User said: ${userInput}`;
console.log(safe); // "User said: &lt;script&gt;alert(&#39;x&#39;)&lt;/script&gt;"

// Example 4: Tagged template to format currency
function currency(strings, ...values) {
  // Example: format numeric values as USD currency
  return strings.reduce((out, str, i) => {
    const val = i < values.length && typeof values[i] === 'number'
      ? new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).format(values[i])
      : (i < values.length ? values[i] : '');
    return out + str + val;
  }, "");
}

const price = 49.99;
console.log(currency`Total: ${price}`); // "Total: USD 49.99" (Intl formatting may include currency symbol and localization)
```
