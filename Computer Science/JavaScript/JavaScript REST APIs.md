# **Purpose/Why**:

---
The primary application of a "JavaScript REST API" is to ==use the JavaScript language to both **create** and **consume** web services. Before Node.js, JavaScript was primarily a client-side (browser) language. The advent of Node.js allowed developers to use JavaScript on the server as well.==

This solves a major problem: ==**it allows for a unified language across the entire web development stack** (frontend and backend==). This "full-stack JavaScript" approach simplifies development, reduces context-switching for developers, and enables code sharing between the client and server. JavaScript's asynchronous, non-blocking nature is also exceptionally well-suited for building scalable APIs that need to handle many concurrent connections, a common requirement for modern web services.

# **Core Explanation:**

---

A **JavaScript REST API** refers to a RESTful API built ==using the JavaScript runtime environment **Node.js** and its ecosystem of frameworks, most notably **Express.js**==. It's not a different kind of REST API but rather ==an implementation of the REST architectural style using JavaScript==.

==It works by running a JavaScript application on a server using Node.js. This application listens for incoming HTTP requests to specific endpoints (URIs)==. A ==framework like Express.js is used to simplify the process of handling these requests:==

1. **Routing:** Express defines which function should be executed for a given URI and HTTP method (e.g., a `GET` request to `/users/:id`).
2. **Request Handling:** The function receives the request object (containing information like parameters, headers, and body) and the response object.
3. **Business Logic:** The developer writes logic to interact with a database, perform calculations, or call other services.
4. **Response:** The function uses the response object to send back an HTTP response, typically with a status code and a body containing data in JSON format.

>On the client side, any JavaScript application (e.g., a React, Angular, or Vue app) can then "consume" this API using tools like the built-in `fetch` API or libraries like Axios to make HTTP requests and use the data in the user interface.

# **Related Concepts:**

---
- **[[Node.js - Server-Side JavaScript]]:** The JavaScript runtime environment that allows JavaScript to be executed outside of a browser. It is the fundamental technology that enables server-side JavaScript development and the creation of JavaScript REST APIs.
- **[[JavaScript Express.js]]:** A minimal and flexible Node.js web application framework. It provides a simple API for building web servers and defining routes (e.g., `app.get`, `app.post`), making it the most popular choice for creating REST APIs in the Node.js ecosystem.
- **`fetch` API:** A modern, promise-based JavaScript API for making HTTP requests, available in both browsers and Node.js. It is the primary tool used in client-side JavaScript to communicate with (consume) a REST API.
- **[[JavaScript JSON (JavaScript Object Notation)]]:** Because its syntax is a subset of JavaScript's object literal syntax, JSON is the de facto data format for JavaScript REST APIs. Converting between a JSON string and a JavaScript object is a seamless, native operation (`JSON.parse` and `JSON.stringify`).

# **Examples:**

---
This example shows how to create a very basic REST API with two endpoints using **Node.js** and the **Express.js** framework. To run this, you would need Node.js installed and would install Express via `npm install express`.

```js
// 1. Import the express library, which simplifies handling HTTP requests.
const express = require('express');

// 2. Create an instance of an Express application.
const app = express;

// 3. Define the port the server will listen on.
const port = 3000;

// A mock database of users for demonstration purposes.
const users = [
 { id: 1, name: 'Alice' },
 { id: 2, name: 'Bob' }
];

// 4. Define a route for a GET request to the root URL ('/').
// This is a simple endpoint to confirm the API is running.
app.get('/', (req, res) => {
 // res.send sends a response back to the client.
 res.send('Welcome to the JavaScript REST API!');
});

// 5. Define a route to get all users.
// When a GET request is made to '/api/users', this function will execute.
app.get('/api/users', (req, res) => {
 // res.json automatically converts the JavaScript object/array to a JSON string
 // and sets the Content-Type header to 'application/json'.
 res.json(users);
});

// 6. Start the server and make it listen for incoming connections on the specified port.
// A callback function is executed once the server is successfully running.
app.listen(port, => {
 console.log(`Server is running at );
});
```
