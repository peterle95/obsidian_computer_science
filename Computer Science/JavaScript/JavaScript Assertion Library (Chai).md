    const line = lines[i];
    
    // Track code blocks
    if (line.trim().startsWith('```')) {
        inCodeBlock = !inCodeBlock;
        continue;
    }
    
    // Skip everything inside code blocks
    if (inCodeBlock) continue;
    
    // Check if line contains flashcard separator
    if (line.includes(';;')) {
        flashcardLines.push(line);
    }
}

const filteredLines = flashcardLines.filter(line => {
    // Only filter out lines that are clearly part of the JavaScript code
    // Be more specific with patterns to avoid false positives
    return !(
        line.trim().startsWith('const ') ||
        line.trim().startsWith('let ') ||
        line.trim().startsWith('function ') ||
        line.trim().startsWith('return ') ||

# **Purpose/Why**:
---

In testing, we need to verify that code behaves as expected. Writing raw conditionals (`if` statements) for this is verbose and harder to read. ==Assertion libraries (e.g., **Chai** in JavaScript) provide a cleaner, more expressive, and standardized way to describe expectations in tests==. They improve test readability, maintainability, and help detect regressions more quickly.

# **Core Explanation:**
---
==**Assertion libraries** let you state expectations in tests, such as "this value should equal that value" or "this array should include that element."==  In JavaScript, **Chai** is one of the most popular assertion libraries. <mark style="background: #FF5582A6;">Chai is a BDD / TDD assertion library for node.js and the browser that can be delightfully paired with any JavaScript testing framework.</mark>

<mark style="background: #BBFABBA6;">Chai supports different assertion styles:</mark>
>  - **Assert style** (classic, function-based)
  >- **Expect style** (BDD-like, natural language)
  >- **Should style** (chainable, property-based)  
  
These libraries integrate with test runners (like [[JavaScript Testing Frameworks (e.g., Jest, Mocha, Jasmine) - Overview]], Jest) to provide meaningful error messages when expectations fail. Assertions improve test clarity by making intent explicit.

# **Related Concepts:**
---

- **Unit Testing**: Assertions are the foundation of verifying correctness at the smallest testable units.
- **Test Runners (Mocha, Jest)**: Provide the execution environment for running tests where assertions are evaluated.
- **Mocking/Stubbing (Sinon.js)**: Often used alongside assertions to simulate dependencies.
- **[[JavaScript - Behavior Driven Development (BBD)]]**: Assertion libraries support natural-language styles (`expect`, `should`) that align with BDD.

# **Examples:**
---
```javascript
// Import the Chai assertion library
const chai = require("chai");

// Choose an assertion style (here we use "expect")
const expect = chai.expect;

// Example function to test
function add(a, b) {
  return a + b;
}

// Basic test using assertions
describe("add function", function() {
  it("should return the sum of two numbers", function() {
    // Assertion: we expect add(2, 3) to equal 5
    expect(add(2, 3)).to.equal(5);

    // Another assertion: check type
    expect(add(2, 3)).to.be.a("number");
  });
});

// Demonstrating array assertions
describe("Array tests", function() {
  it("should include certain values", function() {
    const fruits = ["apple", "banana", "cherry"];
    
    // Check inclusion
    expect(fruits).to.include("banana");
    
    // Check length
    expect(fruits).to.have.lengthOf(3);
  });
});
````
