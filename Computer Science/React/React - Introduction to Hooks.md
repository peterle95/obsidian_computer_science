    if (line.trim().startsWith('```')) {
        inCodeBlock = !inCodeBlock;
        continue;
    }

    // Check if line contains flashcard separator

        flashcardLines.push(line);

    // Only filter out lines that are clearly part of the JavaScript code

        line.trim().startsWith('function ') ||
        line.trim().startsWith('return ') ||

# **Purpose/Why**:
---
Before Hooks, state and lifecycle methods were only available in **Class Components**. This led to several issues:
1.  **Complexity**: "This" keyword binding in JavaScript is often confusing.
2.  **Giant Components**: Logic for different features (e.g., data fetching and event listeners) often got tangled within the same lifecycle methods like `componentDidMount`.
3.  **Logic Reuse**: Reusing stateful logic between components required "Wrapper Hell" (Higher-Order Components or Render Props).

**Hooks** solve this by allowing you to use state and other React features in functional components, making code more readable, modular, and easier to test.

# **Core Explanation:**
---
**Hooks** are special functions that "hook into" React state and lifecycle features. They allow you to "split" one component into smaller functions based on which pieces are related.

### Key Characteristics:
* **Functions only**: Hooks do not work inside classes.
* **Top-Level Only**: You must call Hooks at the top level of your React function. Don't call them inside loops, conditions, or nested functions.
* **Built-in Hooks**: The most common are `useState` (for data) and `useEffect` (for side effects like API calls).

### The Rules of Hooks:
1.  **Only Call Hooks at the Top Level**: This ensures that Hooks are called in the same order each time a component renders.
2.  **Only Call Hooks from React Functions**: Call them from React function components or custom Hooks.

# **Related Concepts:**
---
* **Functional Components**: The foundation upon which Hooks are built.
* **State Management**: How data changes over time in an app.
* **Side Effects**: Any operation that affects something outside the scope of the function being executed (e.g., fetching data, changing the DOM).
* **Custom Hooks**: Creating your own Hooks to extract and reuse component logic.

# **Examples:**
---
```javascript
import React, { useState, useEffect } from 'react';

function CounterExample() {
  // useState hook: 'count' is the value, 'setCount' is the updater function.
  // We initialize the state at 0.
  const [count, setCount] = useState(0);

  // useEffect hook: This runs after the component renders.
  useEffect(() => {
    // This is a side effect: updating the document title.
    document.title = `You clicked ${count} times`;
    
    // The dependency array [count] tells React to only re-run 
    // the effect if 'count' has changed.
  }, [count]);

  return (
    <div>
      <p>You clicked {count} times</p>
      {/* Clicking the button triggers setCount, causing a re-render */}
      <button onClick={() => setCount(count + 1)}>
        Click me
      </button>
    </div>
  );
}
```
